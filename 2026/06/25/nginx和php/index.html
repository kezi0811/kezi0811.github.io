nginx和php

发表于 2026-06-25 更新于 2026-08-05

本文梳理 Nginx 的核心原理（上下游、反向代理、负载均衡）与配置文件结构，并结合作者环境记录 Docker 离线部署 Nginx（含反向代理+负载均衡实战）、Nginx 联动 PHP-FPM 解析 PHP 的完整流程，最后给出常用配置片段速查与排错清单。PHP 部分聚焦「Nginx 不解析 PHP、由 PHP-FPM 通过 FastCGI 通信」这一关键机制。

==概述与原理==

Nginx 是高性能、高可靠的 Web 服务器与反向代理服务器，支持热部署，同时可作为负载均衡器、缓存、API 网关。

上下游概念

对用户请求来说：
下游（downstream）：用户/浏览器一侧，请求从下游来。
上游（upstream）：真正处理业务的服务器（Tomcat / Java / PHP / 后端服务）。
链路：用户请求 → Nginx → 上游服务器；响应结果 ← Nginx ← 上游服务器。
静态网页多用 Nginx 直接托管；动态网页一般是 Nginx + Tomcat/PHP（Nginx 在前，业务服务在后）。

反向代理原理（标准流程）

1 客户端向代理服务器（Nginx）发起请求，目标地址是 Nginx 自身。
2 Nginx 接收请求，按规则转发到内网后端真实服务器。
3 后端处理并返回响应给 Nginx。
4 Nginx 把响应转发回客户端。
5 客户端全程无感知后端存在，仅与 Nginx 交互。
核心：代理面向内部服务器，隐藏后端拓扑、统一入口、提供安全隔离。

负载均衡原理（标准流程）

1 负载均衡器维护一组可用后端节点列表。
2 客户端请求统一进入负载均衡器。
3 按调度算法（轮询、加权、IP 哈希等）选一台后端。
4 将请求转发至选中节点。
5 接收后端响应返回客户端。
6 对后端做健康检查，自动剔除异常节点，不再分配流量。
核心：把请求均匀/合理分发，避免单点过载，提高并发与可用性。

Nginx 与 PHP 的关系

Nginx 本身不直接解析 PHP，依靠 PHP-FPM（FastCGI 进程管理器）通信。
流程：用户请求 → Nginx → 转发给 php-fpm 解析 PHP → 返回结果给 Nginx → 浏览器。
关键点：Nginx 只负责把 .php 请求通过 FastCGI 交给 php-fpm（默认 9000 端口），由 php-fpm 执行 PHP 并返回。

==配置文件结构与位置==

一个 Nginx 配置文件从外到内的层级：
全局块（main）→ events 块 → http 块 → http 里的 server 块 → server 里的 location 块
每一级大块内部可再配置本块的全局项。

全局块（main）：运行用户（user）、工作进程数（worker_processes）、错误日志路径与级别、pid 文件路径（用于 nginx -s reload/stop 平滑启停）。
events 块：并发量（worker_connections）。理论最大并发 = worker_processes × worker_connections。
http 块：mime 类型、访问/错误日志、sendfile 零拷贝、tcp_nopush、keepalive 长连接、upstream 后端组、gzip、缓存、限流等。
server 块：监听端口（listen）、字符集（charset）、域名（server_name）。
location 块：root/alias 路径规则、代理转发、重写、缓存等。

配置文件位置（只需在 http 块内配置）：
主配置：/etc/nginx/nginx.conf
子配置（推荐）：/etc/nginx/conf.d/xxx.conf（主配置一般 include 该目录）

root 与 alias 区别

root：拼接规则，location /book/ + root /data ⇒ 实际路径 /data/book/
alias：替换规则，location /book/ + alias /data/ ⇒ 实际路径 /data/（注意 alias 路径末尾要加 /，否则易 404）

==验证与排错==

改配置务必先校验语法（材料里常用 nginx -s reload，强烈建议先 -t）：

排错清单：
容器没起来：docker ps / docker logs my-nginx 看报错；多半是端口冲突或配置挂载路径不对。
访问不通：检查对应端口防火墙是否放行（80/81/8081/8082/9000），以及宿主机端口是否被占用。
负载不生效：确认两台后端 html 是否真的不同、upstream 地址是否可达、weight 是否按预期。
PHP 不解析 / File not found：检查 php-fpm 是否运行、fastcgi_pass 地址是否可达、SCRIPT_FILENAME 是否正确、root 是否指向 PHP 文件所在目录。
root/alias 404：alias 路径末尾漏写 / 是常见坑；root 与 alias 拼接规则不同，按需选择。
想看转发效果：在 location 里加 add_header 或查 access_log，确认请求确实到了后端。
